# MAKCU: контекст, сетап и что где лежит

Точка входа в проект. Актуально на **2026-10-12**. Подробности — в README папок, ссылки ниже.

> ## Идеальный транспорт (берите отсюда)
>
> - **UDP / Ethernet, ~1000 Гц** — [`basics/udp_way/perfect-transport-udp/`](basics/udp_way/perfect-transport-udp/README.md) (`makcu_udp_batch_transport.h`)
> - **COM / USB2, ~1000 Гц** — [`basics/comport_way/perfect-transport-comport/`](basics/comport_way/perfect-transport-comport/README.md) (`makcu_raw_transport.h`)
>
> Один заголовок на WinAPI, одинаковый API (движение, кнопки, инжект, блокировки, автопереподключение).
> English: [`ENG_CONTEXT_AND_SETUP.md`](ENG_CONTEXT_AND_SETUP.md).

> ## ⚠ Обязательная настройка Windows для UDP: брандмауэр
>
> Плата присылает события кнопок `0x53` **с порта, равного порту программы, а не с 8080**. Если сеть с
> платой помечена как **Public** (у нас интерфейс `Ethernet` — Public), брандмауэр Windows **молча
> режет** эти пакеты для любой программы без разрешающего правила. Движение при этом работает, а кнопки
> держатся только на запасном опросе 5 мс (в `statsLine()`: «СОБЫТИЯ НЕ ДОХОДЯТ»).
>
> **Один раз, PowerShell от администратора**, один из вариантов:
>
> ```powershell
> # разрешить входящие UDP только от платы, для любой программы (рекомендуется; у нас сделано 2026-10-12)
> New-NetFirewallRule -DisplayName "MAKCU UDP events" -Direction Inbound -Protocol UDP -RemoteAddress 192.168.50.175 -Action Allow
> ```
>
> или пометить сеть как частную (у нас брандмауэр Private выключен):
>
> ```powershell
> Set-NetConnectionProfile -InterfaceAlias "Ethernet" -NetworkCategory Private
> ```
>
> **Если IP платы сменится** (DHCP), правило с `-RemoteAddress` надо поправить:
> `Set-NetFirewallRule -DisplayName "MAKCU UDP events" -RemoteAddress <новый IP>`.
> Проверка, что правило есть: `Get-NetFirewallRule -DisplayName "MAKCU UDP events"`.

## 1. Цель и итог

**Цель:** модуль на C++, который двигает курсор через плату **MAKCU** с частотой **1000 Гц**, с точным
путём (сколько отправили, столько пришло в Windows), и читает кнопки мыши. Основной канал — **локальная
сеть (UDP)**, чтобы в Windows не было COM-порта платы. Запасной канал — COM.

**Итог:**

| Канал | Движение | Как | Эталон |
| --- | --- | --- | --- |
| COM (USB2, CH343) | **~1000 Гц**, путь точный | Raw `0x69` + квитанции `0x6A` | [`basics/comport_way/perfect-transport-comport/`](basics/comport_way/perfect-transport-comport/README.md) |
| UDP (Ethernet) | **~1000 Гц** (970–1001 Гц, 99 % интервалов 1 мс), путь точный | batch `0x6C`, замкнутый цикл, ≤ 7 записей в пакете | [`basics/udp_way/perfect-transport-udp/`](basics/udp_way/perfect-transport-udp/README.md) |

Оба эталона читают **физические кнопки мыши** (левая, правая, средняя, две боковые): `buttons()`,
`buttonDown()`, `pressCount()`. Оба — один заголовок на WinAPI, их можно подключать в одну программу.

Оба эталона (ревизия 3, один и тот же API) дополнительно умеют: **нажимать кнопки программно**
(`press`/`release`; до Windows по UDP ~1.5 мс, по COM ~1 мс), **блокировать физический ввод**
(`setLock`: кнопки, оси, направления — игра не видит, транспорт видит), **сами переподключаются**
после обрыва (UDP — сеть, COM — выдернутый USB2) и восстанавливают блокировки, а `open()`/`close()`
приводят плату в чистое состояние.

Состояние проверки на 2026-10-12:

| | UDP ревизия 3 | COM ревизия 3 |
| --- | --- | --- |
| движение 1 кГц, путь точный | да | да (2000 = 2000, soak 2 мин: 999 Гц, 99.8 % по 1 мс) |
| клики `--clicks` | 25/25 | 25/25, ср 0.75–1.19 мс |
| блокировки `--locks` (физика не доходит до Windows) | да | да (прогнал владелец, цифры не записаны) |
| блокировка осей `--axes` (X, Y, +X, −Y: физика не доходит до Windows) | да, 0 отсчётов в заблокированном направлении | да, 0 отсчётов |
| переподключение `--reconnect` | да, 14.3 с после кабеля | да, после выдернутого USB2 (прогнал владелец) |
| долгий прогон `--soak 30` | 2 мин чисто, на 3-й умер USB3 платы (прошивка, см. §4) | 14 мин чисто (606 938 записей без потерь), на 15–16-й прерван снаружи; полные 30 мин подряд не пройдены |

## 2. Аппаратный сетап

Разъёмы MAKCU:

| Разъём | Куда | Зачем |
| --- | --- | --- |
| **USB 1** (PC, левый) | ПК | питание + HID-мышь, которую видит Windows (клон дескриптора реальной мыши) |
| **USB 2** (COM, средний) | ПК — **только для COM-пути**; для сетевого сценария отключён | мост CH343 `1A86:55D3`, у нас COM5, 4 000 000 бод |
| **USB 3** (Host, правый) | хаб **UGREEN 60554** | USB-хост платы: мышь + сетевая карта |

Хаб **UGREEN 60554** (USB 3.0 → 3×USB 3.0 + гигабитный RJ45): хаб-чип Genesys Logic `05E3:0610`,
сетевая карта **ASIX AX88179 `0B95:1790`** (не Realtek, как считалось раньше). В тот же хаб вставлен
ресивер **Logitech Lightspeed `046D:C547`**, опрос 1000 Гц. Вход питания USB-C у хаба на результат не влияет.

Сеть: встроенная сетевая карта ПК Realtek 2.5GbE (линк 1 Гбит/с) → свитч → RJ45 хаба.

> Частота инжекта не может превысить частоту опроса мыши в USB 3: плата копирует её интервал.
> Мышь 125 Гц даст 125 Гц инжекта.

`MAKCU Virtual COM Port (COM8)` в диспетчере устройств — отдельный канал для Toolkit, к сетевому пути
отношения не имеет.

## 3. Сеть

| | |
| --- | --- |
| IP платы | `192.168.50.175` (DHCP роутера; MAC `6c-1f-f7-c5-c6-68`, OUI Ugreen) |
| Порт команд | UDP `8080` |
| IP ПК в этой сети | `192.168.50.87` (интерфейс `Ethernet`) |
| Шифрование UDP | выключено (ключ AES записывается в плату один раз и не меняется — не включать без нужды) |
| Брандмауэр Windows | сеть `Ethernet` = **Public**, брандмауэр Public включён. Добавлено правило **«MAKCU UDP events»**: входящий UDP от `192.168.50.175` для любой программы. Без него события кнопок по UDP режутся — см. блок «Обязательная настройка» в начале файла |

Если плата получила другой IP — найти её по MAC `6c-1f-f7-...` и передать `--host`.

## 4. Прошивка

- Сейчас стоит **V4.097**. С 2026-10-11 это **официальная** прошивка MAKCU (`current_official` в их
  MCP `firmware_versions`); до этого мы ставили её как тест-сборку, выданную поддержкой. В ней впервые
  есть batch **`0x6C`**, на нём держится UDP 1000 Гц. Более старые сборки (V4.095 и раньше) `0x6C` не
  умеют — на них не откатываться.
- Тест-сборки поверх 4097: **V4.098** (USB3-сторона сама перезапускается после зависания) и **V4.099**
  (+ инжект у беспроводных ресиверов больше не придерживается после 9–18 с простоя мыши — наш случай с
  Lightspeed). Обе на 2026-10-12 «not yet tested on hardware».
- Интерполяция `0x1F` = 0. На Raw/batch она не влияет.
- Переписка с инженерами MAKCU (через LLM-бота поддержки в Discord) и все замеры:
  [`basics/udp_way/MAKCU_RESPONSE_UDP.md`](basics/udp_way/MAKCU_RESPONSE_UDP.md).

## 5. Протокол на проводе

Кадр MAK_API: `DE AD | LEN u16 | CMD u8 | PAYLOAD`. По UDP — обёртка RAW:
`0x55 | nonce u64 | DE AD | LEN | CMD | PAYLOAD`, ответ несёт тот же nonce. Голый кадр без обёртки
плата по UDP игнорирует. Одна команда на датаграмму.

Что для чего:

| Задача | Команда | Замечание |
| --- | --- | --- |
| Движение 1000 Гц по UDP | **`0x6C` batch** | ≤ 7 записей `(id, x, y, dt)` в пакете, одна квитанция; ждать квитанцию, `X` = старший терминальный id из неё |
| Движение 1000 Гц по COM | **`0x69` RAW_MOVE + `0x6A`** | каждая запись = ровно один HID-отчёт; по UDP только ~284 Гц (2 датаграммы на ход) |
| Движение «по-старому» | `0x18` MOVE | через интерполятор прошивки: по COM ~640–700 Гц, по UDP ≤ ~280 команд/с и без ответа |
| Нажать/отпустить кнопку (инжект) | SET `0x11…0x15` (LEFT…SIDE2), `1`/`0` | без ответа. UDP: после неё пауза ≥ 1.5 мс; COM: пауза не нужна, но команда изредка теряется — сверять снимком |
| Заблокировать физический ввод | SET `0x60` LOCK `target state`; направления движения разом — SET `0x16` MOVE_MASK `left right down up` (колесо `0x17`) | 14 целей; без ответа; инжект и чтение кнопок блокировка не трогает. `0x16` — те же биты одной командой: по UDP физика встаёт через ~1.3 мс (UDP-эталон ревизии 4, `setLocks({X, Y})`), серия `0x60` давала 7.7 мс |
| Проверить инжект и блокировки | GET `0x56` INJECT_SNAPSHOT | `[0]` инжект-кнопки, `[1..2]` маска блокировок |
| Прочитать физические кнопки | **GET `0x55` PHYS_BUTTONS** → маска | bit0 левая … bit4 side2 |
| События кнопок | `0x52` INPUT_STREAM (вкл.) → события **`0x53`** | `DE AD 03 00 53 01 <кнопка> <0/1>`; `FF FF` = переполнение |
| Метаданные Raw | `0x6A` с `id = 0` | `last_accepted_id`, свободные записи (ёмкость 16) |

## 6. Ловушки (на каждой уже теряли время)

1. **UDP: одна команда в полёте.** Каждая команда идёт на второй чип платы по внутреннему каналу, который
   везёт одну команду за раз. Датаграмма, пришедшая во время передачи, **молча выбрасывается**. Поэтому
   замкнутый цикл: следующая команда только после ответа на предыдущую.
2. **GET `0x11…0x15` не видят физическую кнопку** — только инжектированное состояние. Физику даёт `0x55`
   и события `0x53` (и текстовые `km.left()` …).
3. **События `0x53` по UDP приходят с порта платы, равного порту клиента, а не с 8080.** Сокет с
   `connect()` их выбрасывает. Брандмауэр на сети Public режет их без правила из §3.
4. **Событие несёт nonce одной из наших прошлых команд.** Разбирать `0x53` по опкоду до сопоставления
   ответов по nonce, иначе его примут за квитанцию.
5. **Записи Raw на плате живут до перезагрузки.** Прерванная программа оставляет занятые места (их 16) —
   эталоны дочищают их при открытии.
6. **«Повышенная точность указателя»** в Windows искажает путь курсора. Movers выключают её на время работы.
7. **COM-порт эксклюзивный:** открыть его может только одна программа (в том числе SDK mak-suite).
8. **Команды без ответа** (кнопки `0x11…0x15`, блокировки `0x60`, `SET 0x52`) по UDP: следующая команда
   раньше чем через ~1 мс молча теряется. Пауза 3 мс и сверка снимком `0x56`. 2 мс хватает при неподвижной
   мыши, но после опроса платы и с рукой на мыши каждая 4-я команда серии терялась (замер 2026-10-30,
   `HANDOFF_MOUSE_TRACKING.md`). **По COM** паузы не нужно
   (SET → SET/GET без паузы 300/300), но сам `SET` изредка пропадает (0.3–0.7 %, бывает кучкой) —
   сверка снимком обязательна и там (снимок по COM отвечает за ~0.3 мс).
9. **Блокировка оси = два бита** (+ и −); бит оси целиком плата выставляет сама. Снять «+X» при
   заблокированной оси X — останется только «−X».
10. **Инжектированные кнопки и блокировки прошивка сама не снимает.** Программа упала или закрылась без
    связи — они остаются на плате до следующего `open()` эталона (он чистит) или перезагрузки платы.

## 8. Сборка и запуск

- Компилятор: MinGW-w64 g++ 15.3 (`C:\mingw64\bin`), C++23 для movers, C++17 хватает эталонам.
- `basics\udp_way\build.bat`, `basics\comport_way\build.bat` — movers; `build_example.bat` в папке
  каждого эталона.
- Самопроверка: `example_line.exe --check` (связь), `example_line.exe` (2 с движения, мышь не трогать),
  `example_line.exe --buttons 15` (кнопки). Для UDP-эталона добавить `--host <IP>`, если IP другой.
- Кнопки/блокировки/обрыв/долгий прогон: `controls_test.exe --clicks | --locks S | --axes S | --reconnect S |
  --soak M | --draw S | --watch S` в папке каждого эталона (UDP: `--host`, COM: `--port`). Своё окно,
  курсор заперт в нём, Esc — выход.
- Python-пробы: `.venv\Scripts\python.exe` или `C:\anaconda3\python.exe` (у него есть разрешающее
  правило брандмауэра).
