# Руководство по архитектуре и настройке MAKCU (Pure UDP / Single PC)

Этот документ детально фиксирует архитектуру, физическое подключение, сетевую топологию и протокол управления платой **MAKCU** исключительно через локальную сеть по **UDP без использования COM-порта**.

---

## 1. Контекст задачи и цель

* **Цель:** Управлять курсором мыши (перемещение `MOVE`, клики) на **одном компьютере (Single PC)** полностью без создания / открытия COM-порта в Windows (чтобы устройства класса `Ports (COM & LPT)`, `CH340/CH343` отсутствовали в диспетчере устройств и не детектировались античитами вроде Vanguard, EAC, BattlEye).
* **Решение:** Плата MAKCU получает питание и отдаёт ввод в ПК по USB 1 как обычная HID-мышь, а управляющие команды принимает по локальной сети через протокол **UDP** на порт **8080**.

---

## 2. Физическое подключение (Аппаратный сетап)

Плата MAKCU (прошивка **MAKCU V4.076 на базе MAKOS**) имеет 3 разъёма:

| Разъём MAKCU | Куда подключён | Назначение |
| :--- | :--- | :--- |
| **USB 1 (PC, левый)** | Напрямую в USB-порт целевого ПК | Питание платы 5V + вывод аппаратно эмулируемого HID-устройства (мышь) в Windows. |
| **USB 2 (COM, средний)** | **ПОЛНОСТЬЮ ОТКЛЮЧЁН** | Физически отключён. В Windows отсутствует COM-порт. |
| **USB 3 (Host, правый)** | Вход USB-хаба **UGREEN** со встроенным RJ45 | USB Host шина MAKCU. |

### Подключения к USB-хабу UGREEN:
1. **В USB-порт хаба:** Вставлена физическая мышь (Logitech Lightspeed ресивер `VID: 0x046D, PID: 0xC547`).
2. **В порт RJ45 хаба:** Вставлен сетевой Ethernet-патчкорд, идущий в локальный сетевой свитч (свитч подключён к роутеру и к ПК).

> **Как работает аппаратный проброс (Passthrough):**  
> Встроенный в ESP32-S3 стек USB Host опрашивает ресивер мыши из хаба и прозрачно передаёт физические движения в порт USB 1 целевого ПК. Курсор реальной мыши работает на ПК в штатном режиме.

---

## 3. Сетевая топология и адресация

* Внутри USB-хаба UGREEN расположен USB-to-Ethernet контроллер (Realtek RTL8152/8153).
* Прошивка MAKCU (MAKOS) содержит встроенный драйвер USB Host сетевого адаптера и сетевой стек **lwIP**.
* При подключении сетевого кабеля плата MAKCU через DHCP роутера получает локальный IP-адрес:
  * **Текущий IP MAKCU:** `192.168.50.175`
  * **MAC-адрес:** `6c-1f-f7-c5-c6-68` (OUI: *Ugreen Group Limited*)
  * **Пинг:** `<1 мс`, `TTL=64` (сетевой стек lwIP)
  * **Порт команд:** `8080` (UDP)

## 4. Главный секрет протокола: Режим UDP `RAW` (`UdpWireMode.RAW`)

### В чём была проблема изначально:
По умолчанию в библиотеке `mak-suite` и скриптах UDP отправлялся в режиме `UdpWireMode.HOST` (чистый кадр `DE AD ...`).  
Прошивка MAKCU при приёме пакетов через Ethernet-прокси **молча отбрасывала такие пакеты**, требуя заголовок транзакции.

### Как устроен правильный пакет (UdpWireMode.RAW):
Каждый UDP-пакет **обязан** начинаться с байта `0x55` и 8 случайных байт номера транзакции (nonce), за которыми следует бинарный кадр MAK_API:

```text
[ 0x55 ] + [ 8 байт nonce ] + [ 0xDE 0xAD ] + [ LEN : uint16_le ] + [ CMD : uint8 ] + [ PAYLOAD ]
```

* `0x55` — маркер режима RAW.
* `8 байт nonce` — случайные байты идентификатора транзакции (`secrets.token_bytes(8)`).
* `DE AD` — магический заголовок MAK_API.
* `LEN` — 2 байта (Little-Endian), длина полезной нагрузки `PAYLOAD` (без учёта `CMD`).
* `CMD` — опкод команды.

---

## 5. Спецификация команд управления

### 1. Перемещение мыши (`MOVE` / Opcode `0x18`)
* `LEN` = 4 байта (`\x04\x00`).
* `PAYLOAD` = `x: int16_le` (2 байта), `y: int16_le` (2 байта).
* **Сырой кадр:** `DE AD 04 00 18 <x_low> <x_high> <y_low> <y_high>`
* **В режиме RAW UDP:** `0x55 + nonce(8) + DE AD 04 00 18 + struct.pack("<hh", dx, dy)`

### 2. Кнопки мыши (`LEFT` 0x11, `RIGHT` 0x12, `MIDDLE` 0x13)
* `LEN` = 1 байт (`\x01\x00`).
* `PAYLOAD` = `0x01` (нажатие) / `0x00` (отпускание).
* **ЛКМ Нажать:** `DE AD 01 00 11 01`
* **ЛКМ Отпустить:** `DE AD 01 00 11 00`

### 3. Проверка устройства (`DEVICE` / Opcode `0x02`)
* Запрос: `DE AD 00 00 02`
* Ответ платы: `55 + nonce(8) + DE AD 01 00 02 03`  
  *(где `0x03` = битовая маска 0x01 (Mouse) | 0x02 (Keyboard))*.

## 7. Важные замечания для будущих сессий
1. Если роутер перезагрузится или плата получит другой IP по DHCP — нужно проверить актуальный IP адрес устройства в сети (MAC вендора `Ugreen` `6c-1f-f7-...`).
2. В WebUI MAKOS на странице *«Безопасность»* опция `UDP-API-шифрование` отключена. Если в будущем включить шифрование, в `ConnectionConfig.udp` нужно будет передавать параметр `aes128_key`.
3. Для работы со скриптами активируйте виртуальное окружение: `.venv\Scripts\activate` или запускайте напрямую `.venv\Scripts\python.exe <скрипт>`.

## 8. Аппаратная база, физика движений Windows и 4K-калибровка
1. **Аппаратный Polling Rate MAKCU:**
   - Команда `km.device()` возвращает: `R:MK;M:8uf;K:8uf;C:0uf`.
   - `M:8uf` = 8 USB High-Speed микрофреймов по 125 мкс = ровно **1.000 мс (1000 Гц)**.
   - Плата отправляет HID-отчёты в ПК ровно 1000 раз в секунду.
2. **Отсчёты мыши (Mickeys) против экранных пикселей на 4K:**
   - USB HID мышь оперирует не пикселями монитора, а относительными отсчётами сенсора (*mickeys*).
   - На мониторе **4K Ultra HD (3840x2160)** при стандартной чувствительности Windows (MouseSpeed=0, Sens=10, 150% DPI):
     - При включенном фильтре `mouse_spread=50%` (по умолчанию в старой прошивке) половина мелких шагов тонула в окне 17 мс, давая искусственную пропорцию $4.35\times$.
     - При **отключенном фильтре (`mouse_spread=0%`)** каждый отсчет передается в Windows напрямую, и реальный масштаб составляет ровно **$2.17\times$** (1 экранный пиксель = 2.17 отсчета).
   - Чтобы курсор на 4K-мониторе прошёл **честные 250 экранных пикселей**, требуется отправить:
     $$250 \times 2.17 = 542.5\ \text{отсчётов (counts)}$$
3. **Синхронизация разрешения экрана:**
   - По умолчанию MAKCU хранит размер виртуального экрана `km.screen(1920, 1080)`.
   - Внимание: вызов `km.screen` аппаратно центрирует курсор на экране.
4. **Оптимальная частота инжектов и решение через ABCurves:**
   - С отключением аппаратного фильтра размазывания (`mouse_spread=0%`) и интеграцией **ABCurves SubStepper** частоты **500 Гц и 1000 Гц** работают нативно: Q16 аккумулятор квантует субпиксельные перемещения без потери дельт, а спиральный рамп-ин (ramp-in) исключает стартовые рывки.

## 9. Интеграция субстеппера ABCurves (Нейрорендерер микро-кинематики)

### Архитектура модуля:
1. **Ядро субстеппера (`abcurves_substepper.py`):**
   - Нативная 64-битная библиотека: `ABCurves\abcurves\_native\abcurves_renderer.dll`.
   - Замороженная бинарная модель (zero-copy): `ABCurves\models\renderer_global_h80.bin`.
   - Прогрев профиля: 256 тиков нейтрального физического контекста (`(0, 0)`).
   - Кинематический профиль: Flash & Hogan Minimum Jerk ($10\tau^3 - 15\tau^4 + 6\tau^5$) с хвостовыми settling-тиками для полного сброса Q16 долга.
2. **Контроллер мыши (`udp_mouse_controller.py`):**
   - Реализует класс `MakcuUdpController`.
   - Протокол: `UdpWireMode.RAW` (`0x55` + 8 байт nonce + бинарный фрейм MAK_API `0xDE 0xAD 0x04 0x00 0x18`).
   - Подавление избыточных нулевых пакетов: при `(dx, dy) == (0, 0)` UDP-пакет не высылается, предотвращая переполнение USB-хоста ESP32 при параллельном движении физической мышью рукой.
   - Пауза после `m.screen`: 50 мс для завершения внутренней реконфигурации разрешения в ESP32.
3. **Smoke-тест (`test_abcurves_smoke.py`):**
   - Автоматическая проверка DLL, модели, Q16 аккумулятора, связи с платой и тестового движения.
4. **Интерактивный тестер (`mouse_pattern_tester.py`):**
   - Бэкенд `MakcuAbcurvesClient` (опция 3, 1000 Гц + Q16) стал основным рекомендуемым бэкендом.
   - Поддерживает непрерывное сглаживание `step_smooth` для линий, кругов, восьмерок и скачков A->B.
